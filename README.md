## My Problem-Solving Approach

When I tackle a problem, I usually follow this thought process:

1. **Read carefully** - Understanding the problem is significant
2. **Think of examples** - Work through a few test cases manually
3. **Identify patterns** - What data structures or algorithms come to mind ? 
4. **Start simple** - Get a working solution first, then optimize
5. **Test edge cases** - Empty inputs, single elements, duplicates, etc.

## Learning Tips That Helped M

### For Arrays:
- **Prefix sums** are your friend for range queries
- **Two pointers** work wonders on sorted arrays
- **Sliding window** is perfect for subarray problems
- Don't forget about **in-place** modifications!

### For Strings:
- **Two pointers** can solve many string problems elegantly
- **Stack** is great for nested structures (brackets, etc.)
- **Hash maps** for character frequency tracking
- Sometimes **regex** can simplify things (but don't overuse it!)

### For Trees:
- **DFS** for exploring depth-first
- **BFS** for level-order traversal or shortest paths
- **Recursion** often leads to cleaner code
- Remember the **base case**!

### For Graphs:
- **DFS** for connected components
- **BFS** for shortest path problems
- **Union-Find** for connectivity queries
- Think about **cycle detection**!

### For Dynamic Programming:
- Start with a **recursive solution**
- Add **memoization** to avoid recomputation
- Look for **optimal substructure**
- Sometimes **space optimization** is possible!
